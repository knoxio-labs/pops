# FeatureTrips

`TripsRootView(repository:documents:)` presents native Today, Plan and Inbox tabs alongside the system Search tab. Search uses the prominent tab role on iOS 27. Its destination immediately activates the native bottom-toolbar search field and shares the query with results through the Trip model. Dismissing Search returns to the originating tab. Search text survives tab changes; the system clears it when its Close action dismisses the search. All share one explicit Trip selection. Documents remains a contextual shortcut; bookings, date grouping and source details stay in the Trip context. The app supplies authenticated `TripsReading` and `DocumentsReading`; this package imports neither the generated client nor another feature. `BFMTripsRepository(client:)` implements that seam in BFMClient.

The optional `routeReader` binds the selected Trip’s Plan tab. The app binds it to the paired `BFMTripRouteRepository`; callers without it see an explicit unbound Plan state and retain source browsing in Today. Plan walks the producer's mixed route order and gap-associated paths without sorting by dates or reusing legacy journey-group selection. Applied paths remain labelled history. Sources outside active placement stay separately identified. Producer-reported missing sources suppress stale local detail; a reference absent only from the independent detail read remains unresolved, not deleted. Empty, missing, loading and failed routes are distinct. Selection fences discard late responses even after returning to the same Trip. Route and detail reads complete independently and do not promise an atomic snapshot: Today remains available on route failure, while Plan can retain structure when detail reading fails. Plan uses compact visit and journey summaries; expanding a visit exposes its recorded sources without repeating full detail cards. Source actions open the same canonical detail, and empty visits have no disclosure. Plan currently reads existing structure; it grants no route mutation authority.

The selected Trip uses a compact navigation title. Its Timeline leads with a source-backed masthead, an active Now card and a compact summary of the earliest tied Next starts. Later future sources remain in the full chronology. During active or travel-day focus, Needs you and the recorded Visit rail follow Now and Next; a before-trip overview keeps the Visit rail near its countdown. Local search lives inside disclosed Timeline options, and app-level Search remains separate. Current glance cards retain exact checkout and useful addresses while references and notes remain available by opening the source. Each card keeps one indicator in its header using the native NavigationLink indicator-visibility API.

The countdown names the next source with a resolved future start; it never parses `Trip.when` as a start date or claims a total Trip duration. A Travel day heading requires a selected journey's resolved departure on the current display day. Visit cards navigate to the same Timeline and keep partial or approximate dates open; they do not classify a family stay or imply a booking from colour. Journey endpoints show their own recorded zones; day-only and unresolved clocks remain distinct. Compact Next summaries retain independent source states; multi-leg journey state is explicitly scoped to its departure leg. The approved mint route colour and spacious card shape adapt to system appearance. Accessibility text sizes stack chapter and endpoint layouts, move card decorations above full-width headings, and wrap dates, clocks and zones as separate text groups.

Opening a source presents practical timing cards followed by its recorded references, address, notes and source links. These details preserve independent state fields and exact selectable reference values; a document URI alone never claims that an original is available locally.

Trip selection is explicit and shared by Today, Plan, Inbox and app-level Search. Each selected-Trip tab owns its navigation stack; only the active tab receives a source destination, and switching tabs clears that destination. Destination bindings retain their presentation epoch and Trip identity, so an obsolete callback cannot dismiss or reopen a newer destination after returning to the same tab or Trip. Search opens a matching source back in its Trip context and resolves its current record by owner Trip and source identity, rather than keeping a copied search-detail record. A navigation-intent fence rejects late reader success or failure even when the user returns to the same Trip; an earlier selection cannot reopen its detail. The selected source snapshot supplies visit order, contextual source details, date grouping and bookings. Now uses valid active intervals; Next and Now and Next bookings include known future starts across supported record kinds regardless of an unknown or conflicting end. Conflicting recorded times remain visible as warnings; they never form an active interval. Next retains chronological order. Missing clocks or zones never acquire a midnight or UTC fallback. Ambiguous and nonexistent local clocks stay unresolved.

Visits retain the mobile detail contract’s order; journey order is independent in that read contract. The Timeline retains every original, including alternatives, until its explicit alternative filter excludes them through group membership; purchase never selects a journey. Now and Next use the selected sources. Day/month grouping, booking-date scope, inclusive date range and in-context search filter the same snapshot. Ordered recorded date spans can overlap a range without acquiring clocks or completed-travel state; contradictory endpoints remain separate facts. Unresolved dates remain visible, and reversed range selections display a warning. App-level Search retains every original. Booking intention, arrangement and purchase stay independent. Past bookings use explicit source end times, not audit timestamps. Source endpoints and their original zones remain visible in their own record.

The native repository explicitly calls the day-aware BFM
`GET /mobile/v2/trips/:id` operation. The legacy detail wire remains unchanged for
installed clients. Journey endpoints retain an optional day-only `date`
independently of clock resolution.
The Timeline shows its recorded day with time unknown; day/month grouping and range
filters keep it on that day in every display zone. Independent day-only departure
and arrival points do not establish an all-day interval, Now state or Next instant.

The current read contract supplies trips, places, visits, journeys, stays, events and explicit document associations. Every event remains visible with its independent intention, arrangement and purchase. Documents originals use their own IDs and independently granted `documents.read` service; Inventory link IDs and opaque source URIs never substitute for originals. Trip documents lead the ordered visit groups; journeys stay separate because this detail snapshot does not carry mixed route order. Multiple associations preserve one original identity and remain visible in its own source page.

Document metadata does not establish file availability. Open File streams actual bytes through authenticated BFM access and uses the standard native preview. A preview owns a transient file removed on dismissal; it is not a persistent offline copy. Missing originals, unavailable services and missing grants remain distinct from an empty association set. Linked people, offline catalogue availability and change history are not part of the current read contract. Association creation instants remain provenance and never determine route order or completed travel.

Pure model/projection tests live here. Root/navigation UI regressions live in `DesignPlaygroundTests`, the existing ViewInspector host; they read this package’s single fictional source fixture without copying it or widening the production dependency graph. Tests use fictional records only inside test resources. Production has no fixture fallback, persisted offline cache or simulated upload/download operation.

Inbox reads captured originals through the optional `captureReader`, independently of route and detail reads. Unbound, loading and failed reads remain distinct from an empty successful workspace. Selection fences reject responses belonging to an earlier selection. Active captures lead; removed captures remain disclosed history. The app supplies the same authenticated capture repository for reading and writing without adding grants. Inbox’s Capture action and the contextual toolbar reopen the same retained per-Trip composer. The composition root optionally supplies a device-authorized writer. Text and original links stay verbatim; classification never organises a source. Drafts and exact submitted operation UUIDs belong to a per-Trip session retained when the composer closes or another Trip is selected. A failed or unconfirmed write retains its original operation for an explicit retry; the composer never silently generates a replacement UUID. Successful responses distinguish the producer’s original receipt from current affected captures. Verified acceptance refreshes the matching selected Inbox, even after composer dismissal; a late write for another Trip cannot refresh or replace the current selection. Receipt projections never substitute for the complete Inbox read. The app supplies owner-bound durable storage under Application Support. It atomically records unsent fields and the exact pending command before dispatch, restores them after process restart without sending, and retains the original receipt separately from newer field edits. A persisted input-edit identity protects a newer draft even when its text returns to the submitted bytes; retries and storage replacements never count as input edits. Storage failure blocks dispatch. The namespace includes BFM origin, device, pairing revision and Trip; ordinary token refresh retains it, while replacement pairing quarantines old files. When the stable root observes a matching confirmed operator revocation plus its persisted wipe tombstone, it removes only that owner’s drafts. Rendered-state observation can coalesce transitions; files from an unobserved removal remain quarantined and inaccessible rather than being adopted by another pairing. Injected previews without a store retain only in-memory state. Draft persistence does not make Trip reads or original document downloads available offline. Attachments can only use accepted Documents task/original identities, never local file metadata.
