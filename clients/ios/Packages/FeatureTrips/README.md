# FeatureTrips

`TripsRootView(repository:documents:)` contains one selected-Trip Timeline and app-level Search. Documents is the Timeline’s separate shortcut; bookings, date grouping and source details stay in the Trip context. The app supplies authenticated `TripsReading` and `DocumentsReading`; this package imports neither the generated client nor another feature. `BFMTripsRepository(client:)` implements that seam in BFMClient.

Trip selection is explicit and shared by the Timeline and app-level Search. Search opens a matching source back in its Trip context and resolves its current record by owner Trip and source identity, rather than keeping a copied search-detail record. A navigation-intent fence rejects late reader success or failure even when the user returns to the same Trip; an earlier selection cannot reopen its detail. The selected source snapshot supplies visit order, contextual source details, date grouping and bookings. Now uses valid active intervals; Next and Now and Next bookings include known future starts across supported record kinds regardless of an unknown or conflicting end. Conflicting recorded times remain visible as warnings; they never form an active interval. Next retains chronological order. Missing clocks or zones never acquire a midnight or UTC fallback. Ambiguous and nonexistent local clocks stay unresolved.

Visits retain the mobile detail contract’s order; journey order is independent in that read contract. The Timeline retains every original, including alternatives, until its explicit alternative filter excludes them through group membership; purchase never selects a journey. Now and Next use the selected sources. Day/month grouping, booking-date scope, inclusive date range and in-context search filter the same snapshot. Ordered recorded date spans can overlap a range without acquiring clocks or completed-travel state; contradictory endpoints remain separate facts. Unresolved dates remain visible, and reversed range selections display a warning. App-level Search retains every original. Booking intention, arrangement and purchase stay independent. Past bookings use explicit source end times, not audit timestamps. Source endpoints and their original zones remain visible in their own record.

The current read contract supplies trips, places, visits, journeys, stays, events and explicit document associations. Every event remains visible with its independent intention, arrangement and purchase. Documents originals use their own IDs and independently granted `documents.read` service; Inventory link IDs and opaque source URIs never substitute for originals. Trip documents lead the ordered visit groups; journeys stay separate because no mixed route order is published. Multiple associations preserve one original identity and remain visible in its own source page.

Document metadata does not establish file availability. Open File streams actual bytes through authenticated BFM access and uses the standard native preview. A preview owns a transient file removed on dismissal; it is not a persistent offline copy. Missing originals, unavailable services and missing grants remain distinct from an empty association set. Linked people, offline catalogue availability and change history are not part of the current read contract. Association creation instants remain provenance and never determine route order or completed travel.

Pure model/projection tests live here. Root/navigation UI regressions live in `DesignPlaygroundTests`, the existing ViewInspector host; they read this package’s single fictional source fixture without copying it or widening the production dependency graph. Tests use fictional records only inside test resources. Production has no fixture fallback, persisted offline cache or simulated upload/download operation.

Capture is a contextual action inside the selected Trip, not another destination. The composition root optionally supplies a device-authorized writer. Text and original links stay verbatim; classification never organises a source. Drafts and exact submitted operation UUIDs belong to a per-Trip session retained when the composer closes or another Trip is selected. A failed or unconfirmed write retains its original operation for an explicit retry; the composer never silently generates a replacement UUID. Successful responses distinguish the producer’s original receipt from current affected captures. The app supplies owner-bound durable storage under Application Support. It atomically records unsent fields and the exact pending command before dispatch, restores them after process restart without sending, and retains the original receipt separately from newer field edits. A persisted input-edit identity protects a newer draft even when its text returns to the submitted bytes; retries and storage replacements never count as input edits. Storage failure blocks dispatch. The namespace includes BFM origin, device, pairing revision and Trip; ordinary token refresh retains it, while replacement pairing quarantines old files. When the stable root observes a matching confirmed operator revocation plus its persisted wipe tombstone, it removes only that owner’s drafts. Rendered-state observation can coalesce transitions; files from an unobserved removal remain quarantined and inaccessible rather than being adopted by another pairing. Injected previews without a store retain only in-memory state. Draft persistence does not make Trip reads or original document downloads available offline. Attachments can only use accepted Documents task/original identities, never local file metadata.
