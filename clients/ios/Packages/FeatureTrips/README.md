# FeatureTrips

`TripsRootView(repository:documents:)` presents Today, Plan and Inbox as the trip tabs alongside the native Search tab. Search uses the prominent tab role on iOS 27, immediately activates the native bottom-toolbar search field and shares its query with results through the Trip model. Dismissing Search returns to the originating tab. Search text survives tab changes; the system clears it when its Close action dismisses the search. All destinations share one explicit Trip selection. Documents remain available through a trip-level toolbar shortcut; booking details stay in Today and Plan rather than a second list. The app supplies authenticated `TripsReading` and `DocumentsReading`; this package imports neither the generated client nor another feature. `BFMTripsRepository(client:)` implements that seam in BFMClient.

The optional `routeReader` binds the selected Trip’s Plan tab. The app binds it to the paired `BFMTripRouteRepository`; callers without it see an explicit unbound Plan state and retain source browsing in Today. Plan walks the producer's mixed route order and gap-associated paths without sorting by dates or reusing legacy journey-group selection. Applied paths remain labelled history. Sources outside active placement stay separately identified. Producer-reported missing sources suppress stale local detail; a reference absent only from the independent detail read remains unresolved, not deleted. Empty, missing, loading and failed routes are distinct. Selection fences discard late responses even after returning to the same Trip. Route and detail reads complete independently and do not promise an atomic snapshot: Today remains available on route failure, while Plan can retain structure when detail reading fails. Plan uses compact visit and journey summaries; expanding a visit exposes its recorded sources without repeating full detail cards. Source actions open the same canonical detail, and empty visits have no disclosure. Plan currently reads existing structure; it grants no route mutation authority.

Today’s source agenda and filters retain their existing behavior.

The approved mint route colour and spacious card shape adapt to system appearance. Opening a source presents practical timing cards followed by its recorded references, address, notes and source links. These details preserve independent state fields and exact selectable reference values; a document URI alone never claims that an original is available locally.
