# Extractability sandbox

The TypeScript EX-2 sandbox copies a unit at its original repository depth, replaces `@pops/*` workspace dependencies with packed artifacts, installs the unit's declared dependencies, and runs its build or typecheck. Its local workspace file prevents pnpm from resolving dependencies from the checkout. Root dependency patches are projected onto the actual isolated resolved closure. The sandbox first performs a normal lock-only install without the root patch map, then uses the pinned `pnpm list --lockfile-only --json --depth Infinity` for the full graph and each configured exact selector. Only actual canonical package-name/version matches retain their immutable patch bytes and authoritative paths; root metadata and dependency aliases cannot admit a patch. A normal lock-only regeneration must preserve categories, aliases, versions, provenance, transitive edges and deduplication before the final frozen install. Only filesystem paths and root metadata are excluded from graph identity. Install lifecycle hooks remain enabled in every phase, including `pnpm:devPreinstall` during lock-only resolution.

The current internal EX-2 projection protocol supports explicit `package@version` root selectors. Name-only or range selectors fail with an actionable error until their matching protocol is implemented; they are never silently omitted. Missing, malformed or escaping patch files, graph drift and changed workspace policy fail the sandbox. No unused-patch exemption or extra dependency is introduced to make an install succeed.

Monorepo tooling has explicit sandbox providers. When a unit's source uses `oxfmt` or depends on `@pops/contract-openapi`, the sandbox adds the version of `oxfmt` declared in the root `package.json` to the extracted unit. The build-graph guard and its dependency are copied to the relative paths used by package scripts. The root `tsconfig.base.json` is also placed at the path those configs expect. `pack-deps.mjs` has already built each packed `@pops/*` dependency, and the extracted unit's build and typecheck verify those artifacts.

Other package-script commands that reach outside the unit are rejected before dependency packing. The error names the unprovided tool so the package or sandbox can declare an explicit provider.
